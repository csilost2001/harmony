# 保存前の版 (自動バックアップ)

設計ファイルが上書きされる直前の内容を、世代で残す。誤って消した・壊した設計を、あとから確かめて戻せる最小の安全網。

編集セッションの履歴 ([edit-session-protocol.md](edit-session-protocol.md) §13 の draft 履歴。保存・破棄・引継の時点の**編集内容**を 7 日だけ残す) とは別のもので、AI (MCP) や一括操作が直接書き換えた場合も含めて、**ファイルが上書きされる直前の内容**を残す。

## 何が残るか

- 設計ファイル (JSON) を `writeJSON` が上書きするとき、上書き前のファイルの内容を残す (新規作成のときは残るものが無い)
- 内容が同じ保存、直前の版と同じ内容は、残さない (版が増えない)
- 1 ファイルにつき新しい順に **最大 20 世代** (`BACKUP_KEEP`)。古いものから消える
- 8 MB を超えるファイル、隠しフォルダ (`.` で始まる) の中のファイル、`.json` 以外は対象外
- バックアップに失敗しても、保存は止めない (警告ログのみ)

## どこに残るか

`<ワークスペース>/.harmony-backups/<ワークスペースからの相対パス>/<時刻>.json` (例: `.harmony-backups/harmony/tables/orders.json/2026-10-13T05-32-33.778Z-000.json`)。

`.harmony-backups/.gitignore` (`*`) を置くので、利用者の git には載らない。ワークスペースを別の場所へ移すときも、一緒に動く。

改名 (`designer__rename_entity`) で書き換わる**参照元のファイル**も、書き換える前の内容を版に残す (改名後に参照元を編集してから、改名前へ戻したいとき)。改名される設計自身は、ファイルの場所が変わるため、改名前の版は旧 id のフォルダに残る (新 id の版は改名後の保存から)。

## 使い方

| 経路 | 操作 |
|---|---|
| 画面 | 編集画面の編集セッションのメニュー → 「履歴 (過去の draft)」→ 下段「保存前の版」→「この版を読み込む」。読み込んだ内容は**未保存の変更**になり (編集中でなければ、先に編集を始める)、保存するまで原本は変わらない。「変更点」で現在との差を確かめられる。対応: テーブル / 処理フロー / ビュー / ビュー定義 / シーケンス / 業務フロー / 帳票 / ページレイアウト (続編 第 9 弾 #161) |
| AI (MCP) | `designer__list_versions` で一覧、`designer__restore_version` で書き戻す。**通常の保存と同じ書き込み関数**で書き (uuid はいまの設計のものを保つ)、`harmony.json` の一覧の要約 (名前・列数・更新日時など。一覧に載っている項目だけ) も、画面の保存・`update_table` と同じく書き戻した内容に合わせる。書き戻す前の内容も版に残る (取り消せる)。ほかの人・AI が編集中の設計には書き戻せない |

## 実装

- `backend/src/fileBackup.ts` — 上書き直前の保存・世代の管理 (`backupBeforeOverwrite`)・一覧・読み出し
- `backend/src/fileVersions.ts` — 設計の種類 + id からファイルを引く、版の中身の検査 (JSON であること・id が合うこと)
- `backend/src/wsHandlers/versions.ts` — RPC `fileVersions.list` / `fileVersions.get` / `fileVersions.locate` (設計の原本ファイルの場所。画面も引ける。続編 第 9 弾 #179)
- `frontend/src/components/editing/DraftHistoryModal.tsx` — 履歴の画面 (保存前の版の段)
- `frontend/src/utils/applyVersionBus.ts` + `useResourceEditor` — 読み込んだ内容を編集状態へ入れる取り次ぎ

## 限界 (正直に)

- 版は 1 台のマシンのローカルに残るだけ。git のように共有・差分の履歴はない (必要なら git で管理する)
- 20 世代を超えた古い版は消える。頻繁に保存する設計では、数分前までしか遡れないことがある
- ワークスペース全体の容量の上限・削除した設計の版の掃除は無い。長く使うと `.harmony-backups/` が増えるので、必要なら手で消す (消しても設計には影響しない)
- 版を編集画面へ読み込むとき、サーバ側に未送信の新しい下書きがブラウザに残っていても、読み込んだ版が優先される (読み込みは利用者の明示的な操作)
- 画面 (screen-items) は、編集内容が複数ファイルに分かれるため、画面からの読み込みには対応していない (ファイルとしての版は残る。MCP の `restore_version` も画面は対象外)
