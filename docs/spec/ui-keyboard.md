# キーボード・移動 — 仕様書 (UI 改善提案 第 2 弾)

**Status**: 実装済 (2026-10)
**関連**: [ui-input-assist.md](ui-input-assist.md) / [grid-keyboard.md](grid-keyboard.md) / [quick-open.md](quick-open.md) / [ux-operations.md](ux-operations.md)

マウスに手を伸ばさず、探す・飛ぶ・直す・増やす。キー操作の一覧は画面の「?」(ショートカット一覧) が正で、実装と一緒に直す (`utils/shortcuts.ts`)。**原本 (設計の JSON) の形は変えない。**

## 1. 編集画面の中の検索 (Ctrl+F / ⌘F)

- 編集画面 (`/…/edit/…`・画面項目・画面デザイナ・規約カタログ・汎用定義) でだけ、ブラウザの検索の代わりに、画面の中の検索を開く (`components/common/EditorFind.tsx` / `utils/editorFind.ts`)。一覧・ダッシュボードなどでは、ブラウザの検索のまま
- ブラウザの検索では見つからない、**入力欄・選択欄・テキスト欄の「値」** も探す。画面の文字も探す。全角半角・大文字小文字・かなの違いは無視。上限 500 件 (超えると「+」)
- Enter = 次、Shift+Enter = 前、Esc = 閉じる (見つけた入力欄へフォーカスを移す)。日本語の変換中は何もしない
- 見つかった欄は `data-find-hit` の印 (色は `--hm-find-bg` / `--hm-find-current-bg`)。文字は CSS Highlight API (対応していないブラウザでは、欄の印だけ)
- 画面の `#app-main` の中を探す (ヘッダー・タブ・検索欄自身 (`data-find-ignore`) は除く)

## 2. 参照元を探す (Shift+F12)

参照 (`@screen.cart` など) の上で Shift+F12 → その設計を参照している設計の一覧 (「参照元」ダイアログ)。F12 の「定義へ移動」と対 ([ui-input-assist.md](ui-input-assist.md) §1.2)。画面・テーブル・ビュー・ビュー定義・シーケンス・ページレイアウト・処理フローが対象。汎用定義・規約は、案内だけ。

## 3. 表のセルの操作 (useGridKeyboard)

画面項目・カラム (表で編集) の表:

| キー | 動作 |
|---|---|
| Enter / Shift+Enter / ↑↓ / Esc | 従来どおり ([grid-keyboard.md](grid-keyboard.md)) |
| **Ctrl+D** | 1 つ上の行の同じ列の値を、この欄へ写す (入力欄・選択欄とも。先頭の行では何もしない) |
| **Ctrl+Enter** | この行の下に、空の行を挿入 |
| **Ctrl+Shift+Enter** | この行を複製 (元の行の下) |
| **Alt+Delete** | この行を削除 (Ctrl+Z で戻せる) |

行の番号は `<tr data-grid-row>`。挿入・複製のあとは、新しい行の入力欄へ移る。ブラウザの予約キー (Ctrl+Shift+Delete など) は避けた。範囲選択・複数セルのコピーは未対応。

## 4. コマンドパレットに「この画面の操作」

`Ctrl+K` の「>」(または検索語) に、開いている編集画面の操作が出る。画面が `usePageCommands` で登録し (`store/pageCommands.ts`)、キー・ボタンと同じ処理を呼ぶ。登録済み: テーブル (カラムを追加・テンプレートから追加・表から貼り付け・表 / 一覧の切り替え)、画面項目 (項目を追加・テーブルから作る・表から貼り付け・メッセージの下書き)、処理フロー (工程を挿入)、編集画面共通 (この画面の中を検索)。

## 5. ショートカット一覧を画面別に

「?」の一覧は、開いている画面に関係するグループを先頭に、開いた状態で出す (「この画面」の印)。ほかは折りたたむ (`relevantGroupTitles`)。

## 6. 領域の巡回 (F6 / Shift+F6)

ヘッダー → タブ → 画面の中の領域 (`data-region` を付けたもの) の順に、フォーカスを移す。移った領域は枠が光る。領域の印: テーブル (カラム・カラムの詳細)、画面項目 (項目の表)、処理フロー (工程の一覧・メタ情報・マーカー)。新しい画面は、主なパネルに `data-region="名前"` を付ける。

## 7. 工程・部品・図

- 処理フロー: **Shift+↑↓** で、最上位の工程の選択を広げる (Shift+クリックの範囲選択と同じ。Ctrl+C / X / Delete をまとめて使える)。工程の Ctrl+C / X / V・Alt+↑↓・Tab (インデント) は従来どおり
- 画面デザイナ: **`/` または Insert** で、部品を追加するメニュー (種類を打ち込んで Enter。選んでいる部品の後ろに追加。独自部品も出る)
- ER 図・画面フロー: Tab でノードを移り、**Enter で開く** (テーブル編集 / 画面デザイナ)。矢印キーでの移動は従来どおり
- ページレイアウト: region の行で Alt+↑↓ (並べ替え)・Alt+Delete (削除)

## 8. ダイアログのキー (統一)

aria-modal のダイアログは、すべて Tab を中で循環させ、Esc で閉じる。共通の部品: `useFocusTrap(ref, active, onEscape)` (重なったダイアログは、いちばん上のものだけ閉じる。日本語の変換中は閉じない) / `ModalShell`。`utils/dialogKeyboardAudit.test.ts` が、これを満たさないダイアログを止める。Esc の意味: 変更を伴う確認 (上書き・前回の編集の続き) は「取り消し」。

## 9. Ctrl+K の Alt+Enter

候補を開かずに、いまの画面の右側に並べて開く ([ux-operations.md](ux-operations.md) の「並べて表示」)。操作・新規作成は、ふつうに実行する。

## 10. Tab の順序・戻る / 進む

- `tabIndex` に正の値を使わない (`utils/tabOrderAudit.test.ts`)
- 画面の移動 (Ctrl+K・メニュー・リンク) はブラウザの履歴に積まれる。ブラウザの戻る・進む (Alt+←/→) が、そのまま効く (E2E で確認)
