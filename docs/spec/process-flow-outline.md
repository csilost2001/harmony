# 処理フロー: アウトライン (テキスト) 編集 (試作)

処理フローの工程を、1 行 1 工程のテキストで書く表示。カード・図・表と同じ並びの 4 つめ (「アウトライン」) で、保存形式は今の JSON のまま。スキーマは変えない。

## 書式

```
[入力チェック] 入力値を検証する ^step-01
[DBアクセス] カートを取得する ^step-02
[DBアクセス:orders] 注文を取得する    ← :の後が参照先 (テーブルの id)
[共通処理] 在庫を引き当てる
  [計算/代入] 引き当て数を数える ^step-07    ← 字下げ (空白 2 つ) = 直前の工程の配下
```

- `[種類]` は工程の種類の表示名 (入力チェック / DBアクセス / 共通処理 …) か、種類の英名 (`dbAccess`)。
- 行末の `^step-01` は既存の工程との対応づけ (工程の目印)。**無い行は新しい工程**になる。
- 説明の中の改行は `\n`、バックスラッシュは `\\`、`^` は `\^` と書く (行末の `^id` と区別するため。画面ではこの形で出る)。
- 字下げ (空白 2 つ単位) が入れ子 (`subSteps`)。すぐ上の行より 1 段までしか深くできない。タブ・奇数個の空白は誤り。
- 空行は無視する。字下げの誤り・`[種類]` が無い行・知らない種類は、行番号つきで知らせ、反映は止まる。

### 参照先 (`[種類:参照先]`)

参照先を持つ種類は、`[種類:参照先]` と書ける。

| 種類 | 参照先 (JSON の項目) |
|---|---|
| DBアクセス | テーブルの id (`tableId`) |
| 共通処理 | 処理フローの id (`refId`) |
| 画面遷移 | 遷移先の画面の id (`targetScreenId`) |
| 外部システム | システム名 (`systemRef`。`context.catalogs.externalSystems` のキー) |

- 例: `[DBアクセス:orders] 注文を取得する ^step-02`
- 既存の工程で参照先が書かれていなければ、**変えない** (消すには `[DBアクセス:]` と書く)。新しい行では、書かなければ空のまま。
- 参照先を持たない種類 (入力チェックなど) に書くと誤り。
- 行頭の `[DBアクセス` のあとに `:` を打つと、候補 (テーブル・処理フロー・画面・外部システム) の選択が出る。ID・名前で絞り込み、↑↓ Enter で入れる。

## 操作

| 操作 | 結果 |
|---|---|
| 行頭で `/` | 種類を選ぶメニュー (挿入メニューと同じ)。Enter で `[種類] ` を入れる |
| 説明を書き換える | その工程の説明だけが変わる (テーブル・条件・分岐の中身など、ほかの項目は残る) |
| 行を入れ替える | 工程の順序が変わる |
| `Tab` / `Shift`+`Tab` | 選んだ行を字下げ / 戻す (入れ子にする / 外す)。`Esc` で欄を出たあとの Tab は通常のフォーカス移動 |
| 行を消す | 工程が消える (配下の行も、それぞれ消えた行なら消える。「反映」で件数を確かめる。元に戻す操作で戻せる) |
| `^id` の無い行を足す | 種類ごとの既定値で新しい工程ができる |
| `^id` ごと行をコピー | 2 行目は新しい工程になる (元の工程は複製されない) |
| 欄を出る (フォーカスが外れる) | 問題がなく、削除を含まなければ自動で反映。それ以外は「反映」ボタン |
| Esc | 欄から出る |

既存の工程の種類は、テキストから変えられない (種類を書き換えた行は無視して知らせる)。

## できないこと (試作の範囲)

- **分岐の枝・繰り返しの本体などの入れ子**: `subSteps` だけを扱う。ほかの入れ子は、カード表示で編集する (アウトラインでは親の工程の行だけが出て、中身は変えずに残る)。
- 種類・条件・SQL など、説明と参照先以外の詳細の編集 (カード表示で行う)。
