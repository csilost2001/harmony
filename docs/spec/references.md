# 参照元 (どこで使われているか) — 仕様書

**Status**: 実装済 (2026-10)
**関連**: [quick-open.md](quick-open.md) / [design-document.md](design-document.md) / [business-flow.md](business-flow.md) / [report.md](report.md)

## 1. 目的

ある設計 (画面・テーブル・処理フロー等) を**誰が参照しているか**を、改名・削除の前や、設計を辿るときにすぐ分かるようにする。ID の改名 (`RenameEntityDialog`) は参照を一括で書き換えるが、その前に「どこに影響するか」を見たい、そもそも「これは何から使われているのか」を知りたい、という日々の疑問に答える。

## 2. 対象

調べられる設計: 画面 (`screen`)・テーブル (`table`)・処理フロー (`processFlow`)・シーケンス (`sequence`)・DB ビュー (`view`)・ビュー定義 (`viewDefinition`)・ページレイアウト (`pageLayout`)。改名できる設計と同じ。

## 3. 参照元の集め方 (`backend/src/references.ts`)

ID の改名と**同じ走査** (`previewEntityRename`、存在しない ID への改名の予行) で、参照している場所を集める。つまり「改名したら書き換わる場所」が参照元。これに、業務フロー (`screenRef` / `processFlowRef`) と帳票 (出力契機・項目の出どころ) の予行も加える。

| 参照元の種類 | 内容 |
|---|---|
| 画面 / 処理フロー / テーブル / シーケンス / DB ビュー / ビュー定義 / ページレイアウト | その設計の中に参照がある (自分自身の中は除く) |
| 業務フロー / 帳票 | 工程・出力契機・項目から参照 |
| 画面フロー (遷移) | 画面の遷移 (`screenTransitions`) の元・先 |
| 独自部品 / 汎用定義 | 部品の引数・定義からの参照 |

設計の一覧表そのもの (`harmony.json` の `entities` の並び)、図の座標 (`screen-flow-positions.json` / `er-layout.json`) は参照ではないので除く。結果は参照元の設計ごと (種類 + ID + 名前) に、参照している箇所の数を付けて返す。

## 4. 入口

| 入口 | 内容 |
|---|---|
| 画面: 各エディタのヘッダー右「参照元」 (画面デザイナ・画面項目・テーブル・処理フロー・シーケンス・DB ビュー・ビュー定義・ページレイアウト) | ダイアログに種類ごとの一覧。クリックでその設計を開く。**閲覧中も使える** |
| 一覧画面の右クリックメニュー「参照元を見る」 (1 件選択時) | 同じダイアログ |
| WebSocket RPC `findEntityReferences` | `{ entityType, id }` → 結果 |
| MCP `designer__find_references` | AI が、改名・削除の前の影響確認や、設計を辿るために使う |

## 5. 削除前の確認

一覧画面 (画面・テーブル・処理フロー・シーケンス・DB ビュー・ビュー定義・ページレイアウト) で「削除」にしたものを**保存するとき**、削除する設計を別の設計が参照していれば、参照元を列挙して確認する (削除すると参照先を失い「要確認」になる)。同時に削除する設計どうしの参照は数えない。参照を調べられなかったときは、保存を止めない。

## 6. 注意

- 参照を**書き換える**機能ではない (読み取りのみ)。書き換えは ID の改名
- 画面に置いた画面項目の参照など、改名で書き換わらないものは対象外
