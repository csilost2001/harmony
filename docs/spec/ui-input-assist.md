# 入力補助 — 仕様書 (UI 改善提案 第 1 弾)

**Status**: 実装済 (2026-10)
**関連**: [process-flow-prefix-system.md](process-flow-prefix-system.md) (参照 `@prefix` の記法) / [ux-operations.md](ux-operations.md) / [grid-keyboard.md](grid-keyboard.md) / [design-analysis.md](design-analysis.md)

打つ量を減らす入力補助のまとめ。**原本 (設計の JSON) の形は変えない** (スキーマは触らない)。補助が入れた値は、利用者が見て直せる (入れたことを通知し、Ctrl+Z で戻せる)。利用者が決めた値は上書きしない。履歴・設定のように「その人の道具」は、このブラウザの localStorage に持つ。

## 1. 補完 (`@` 参照の入力欄)

共通の部品: `hooks/useReferenceCompletion.ts` / `components/common/CompletionPopup.tsx` (`ReferenceCompletionInput` / `ReferenceCompletionTextarea` が使う)。式の欄は `ConvCompletionInput` (内部は同じ部品)。

- 操作: `@` で自動で開く / **Ctrl+Space** で開く / ↑↓ で選ぶ / **Tab** (input は Enter も) で確定 / **Esc** で閉じる。textarea の Enter は改行
- **日本語の変換中は何もしない** (変換確定の Enter で候補を確定しない。`utils/imeKeys.ts`)
- 候補の並び: 前方一致 → 部分一致の順 (補完ごとの絞り方の違いを、`computeReferenceCompletion` の後処理でそろえる)。全角 / 半角・大文字 / 小文字・ひらがな / カタカナの違いは無視 (`utils/textMatch.ts`)。**1 文字では部分一致にしない** (候補が増えすぎるため。前方一致だけ)
- 選んでいる候補には、`detail` (型・定義元・現在の値) と操作の案内を出す。規約 (`@conv.<種類>.<キー>`) は現在の値、テーブル・画面・処理フローは種別と ID
- 選んだ候補は覚えて (`utils/completionHistory.ts`、localStorage `harmony.completionHistory`、補完ごとに最大 200 件)、**同じ一致の強さの中で**、よく使う・直近のものを上に出す (一致の強さの順は崩さない)
- 入力欄の `title` に使い方を出す
- 式・条件の欄は同じ補完の組 (`utils/reference-completer/expressionPreset.ts`: 規約・`@this`・`@self`・`@stepResult`・`@inputs`・`@var` ほか): 実行条件 (runIf)・分岐条件・代入式・戻り値

### 1.1 SQL の表名・カラム名

`sqlSchemaResolver` (処理フローの DB 工程の SQL 欄)。テーブル定義は `useWorkspaceReferences` が `loadAllTables` 1 回で読んで渡す。

| 位置 | 候補 |
|---|---|
| `FROM` / `JOIN` / `INTO` / `UPDATE` の直後 | テーブルの物理名 (表示名でも探せる) |
| `表名.` / `別名.` の直後 | そのテーブルのカラム (物理名)。別名は `FROM orders o` / `JOIN customers AS c` を読む |
| 単語の途中 (2 文字以上) | FROM / JOIN に出てくるテーブルのカラム (重複は 1 つ。入力済みと同じ名前は出さない) |

`@` で始まる参照は、他の補完に任せる。

### 1.2 定義へ移動 (F12 / Ctrl+クリック)

入力欄の参照 (`@screen.cart` など) の上で **F12**、または **Ctrl (Mac は ⌘) + クリック** で、その定義を開く (`utils/referenceTarget.ts` → ヘッダーの `ReferenceNavigator`)。`@screen` `@table` `@view` `@viewer` `@seq` `@layout` `@flow` は各エディタ、`@conv` は規約カタログ、`@msg` `@exception` などの汎用定義は `/generic-definition/<種類>/<名前>`。参照の上でなければ案内を出す。

## 2. 検索できる選択 (`SearchableSelect`)

候補が **20 件を超える** と、文字を打って絞り込む入力欄になる (それ以下は、ふつうの `<select>`)。名前・補足 (物理名・ID)・ID で探し、表記ゆれを無視する。入力が空のときは、同じ種類の選択で選んだものを上に出す (`historyKey`)。使っている場所: DB 工程のテーブル・画面遷移の遷移先・共通処理・FK の参照先・ER 図の関係・帳票 / 業務フローの画面と処理フロー。

## 3. テーブル・カラム

### 3.1 カラムの物理名・型の提案 (`utils/columnSuggestion.ts`)

新しく足した列 (物理名が `new_column`、型が初期値の VARCHAR) に表示名を入れると、物理名・型・長さ・NOT NULL を入れる (「表で編集」でも「一覧で編集」でも同じ)。

- 物理名: ①同じ表示名の既存の列 (いちばん多く使われているもの) → ②表示名を、既存の列の表示名 + 組み込みの辞書 (`BUILTIN_TERMS`) で長い一致から英語に区切る → ③英数字だけの表示名は規約の表記に整える。**辞書に無い言葉が残るときは入れない** (間違った名前より空のほうがよい)。表記は規約 `@conv.db` の `namingConvention` (snake_case / camelCase / PascalCase / UPPER_SNAKE_CASE / kebab-case)
- 型: 表示名の言葉による規則 (日時・日付・時刻・フラグ・率・金額・数量・ID・メール・電話・名称・コード・備考など)。同じ表示名の既存の列があれば、その型を引き継ぐ
- 決めた物理名・型は変えない。同じ物理名の列が既にあれば、物理名は入れない。**物理名はスキーマの形式 (`^[a-z][a-z0-9_]*$`、63 字まで) のときだけ入れる** (数字で始まる名前・規約が camelCase のときの名前は入れない。スキーマが優先)
- 入れるタイミング: 「表で編集」はセルを出るとき。「一覧で編集」の詳細パネルは、表示名の欄を出るとき (1 文字ずつ打つ途中の語で、物理名が決まってしまわないように)
- 入れたら通知する (「『合計金額』から total_amount・DECIMAL(12,2) を入れました (Ctrl+Z で元に戻せます)」)

### 3.2 名前のヒント (「表で編集」の電球)

同じ表示名がほかのテーブルでは別の物理名 (2 件以上) / 物理名が規約の表記になっていない、ときに行に電球を出し、クリックで合わせる。保存後の「設計の分析」(用語の揺れ・命名規約) を待たずに、その場で気づくため。

### 3.3 外部キーの候補 (制約タブ)

カラム名とテーブル名から推測して、1 クリックで外部キー制約にする (`utils/fkSuggestion.ts`)。①同じ名前の 1 列の主キー (確度 高) ②`<単数形>_id` ↔ 主キー `id` (確度 中)。型の系統が違う・複合主キー・既に外部キーの列・主キー自身は除く。

### 3.4 新規作成

- 表示名を打つと、物理名を (辞書で全部を英語にできたとき) 自動で入れる。物理名を自分で触ったら、以後は上書きしない。ID も同様 (§5)
- **最初のカラム (スターター)**: 空 / 標準 (ID・作成日時・更新日時) / マスタ / トランザクション。カラムの中身は `COLUMN_TEMPLATES` と同じ。選んだものを覚える (既定は「空」)

### 3.5 表から貼り付け (列の対応)

見出しが分からない・順序が違う表でも、列ごとに「何の項目か」を選び直して読める (「列の対応」)。「1 行目は見出し」の切り替えも。貼り付けた文を変えると自動の対応に戻る。

## 4. 画面項目

- **テーブルから作る**: テーブルを選ぶと、カラムから項目の行 (ID = camelCase・ラベル・型・必須・最大長・テーブルのカラムとの紐づけ `binding.tableColumn`) を作る。カラムごとに取捨できる。BLOB など対応しない型は飛ばして知らせる (`utils/itemSuggestion.ts`)
- **ラベルから**: ラベルを入れると、まだ決めていない項目 ID (全部を英語にできたとき) と型・最大長を入れる
- **メッセージの下書き**: 必須・最小 / 最大長・pattern・範囲の設定から、まだ書いていないエラーメッセージ (`required` `minLength` `maxLength` `invalidFormat` `outOfRange`) の下書きを入れる (選んだ行、無ければ全行)。規約に同じキーのメッセージがあれば `@conv.msg.<キー>` の参照にする

## 5. ID の候補

作成ダイアログの ID は、名前から作った候補を最大 3 件出す (`entityIdCandidates`): ①英数字の部分 ②日本語を辞書で英語にしたもの (「顧客一覧」→ `customer-list`)。既存と重なれば番号を付ける。まだ ID を触っていなければ、先頭の候補を自動で入れる。辞書に無い言葉が残る名前は、従来どおり「仮の ID を付ける」か AI 提案。

## 6. 工程の挿入メニューの「おすすめ」

`Insert` / `/` の工程の挿入メニューは、入力が空のとき、直前の工程の後によく置かれる種類を上に出して「おすすめ」を付ける (`utils/stepSuggestion.ts`)。ワークスペースの全処理フロー (1 回の問い合わせ。1 分は使い回す) で、「ある種類の直後に置かれた種類」を数え、**2 回以上** の実績があれば優先する。足りない分は組み込みの目安 (`BUILTIN_NEXT`) で補う。入力があるときは通常の絞り込み。

## 7. 日本語の入力 (IME)

Enter で確定・送信・追加する処理は、変換中を除く (`isImeComposing` / `isPlainEnter`)。`utils/imeEnterGuard.test.ts` が、`key === "Enter"` を見る処理に変換中の確認が無いものを止める (ボタン・ツアーなど入力欄でないものは許可リスト)。

## 8. 辞書について

`BUILTIN_TERMS` は業務の設計書によく出る言葉 (人・取引・商品・金額・属性・分類・日時・フラグ) の対応表で、**完全ではない**。ワークスペースの既存の列の表示名 → 物理名の対応が、辞書より優先される (使っているうちに、その現場の言葉を覚える)。足りない言葉は `utils/columnSuggestion.ts` の `BUILTIN_TERMS` に足す。
