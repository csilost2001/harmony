「ゼロからアプリの設計を始めるとき、簡単に作れるか」を、空のフォルダから実際の画面で通して確かめた結果 (備品貸出管理: テーブル 2・画面 1・画面項目 10・処理フロー 1。約 64 回の操作) の、画面の改善。ISSUE [#1528](https://github.com/csilost2001/harmony/issues/1528) (`type: rfc`) の提案に沿う。スキーマ (`schemas/v3`) は変えない。覚えるもの (案内を見たか) は、ブラウザ内の `localStorage` だけ。

画面の使い方の説明は、[UI 操作リファレンス](../user-guide/ui-reference/README.md) (各ページの先頭に「実画面で確認した日」)。

## 1. 同じ画面の「デザイン」と「項目定義」の行き来 (編集セッションの衝突判定)

同じ画面のデザイン (画面デザイナ) と項目定義は、どちらも `resourceType: "screen-item"` の編集セッションで、**別々の編集**として扱われる。以前は次の問題があった。

- 片方を保存したまま (編集中のまま) もう片方を開くと、「前回の編集の続き (未保存の下書き)」が出た (保存済みなのに「未保存」)
- 保存すると「上書き確認 (別の編集セッションで本体が更新されています)」が出た (相手は自分)。上書きしても、次の保存でまた出た

直し方 (仕様は [edit-session-protocol.md](edit-session-protocol.md) §9.3):

| 場面 | 以前 | いま |
|---|---|---|
| 保存の衝突 | 保存の記録がある別の Active セッションが 1 つでもあれば衝突 | 別のセッションの**最後の保存が、自分の「元」(`baseAt`) より後**のときだけ衝突。自分が始まる前の保存・自分の最後の保存より前の保存は、衝突ではない |
| 別のセッションが保存したあと | 変わらない | 保存していない変更が無い (clean) セッションは、その保存を取り込んだ扱いで、元を進める (画面側は、clean なら変更の通知で読み直す)。保存していない変更があるセッションは進めない (あとで保存すれば衝突) |
| 「前回の編集の続き」の確認 | 自分の Active なセッションがあれば出る | 自分の Active なセッションに、**保存していない変更が残っているとき**だけ出る (`utils/editSessionHints.ts`) |

**本来の衝突は、残る**: 両方のページを開いて、同時に別々の変更をし、あとから保存するほうには、「上書き確認」が出る。

## 2. 小さな改善

| 内容 | 実装 |
|---|---|
| 一覧の開き方の案内 | 一覧の上に 1 行「行 (カード) をダブルクリック、または選んで Enter で開きます」。一度でも開く、または消すと、このブラウザでは以後出ない (`utils/openHint.ts`・`DataList`) |
| 閲覧中の案内 | 帯の「編集開始」の隣に「← 押すと、入力や追加ができるようになります」 (共通の `EditModeToolbar`) |
| 「破棄」 | 保存済み (変更が無い) のときは、「編集を終える」と出る (保存した内容は残る)。変更があるときは「破棄」。確認の文言は、「保存していない変更は失われます (保存した内容は残ります)」 |
| 追加ボタンの名前 | 「〜を追加」にそろえた: テーブルを追加・画面を追加・処理フローを追加・ビューを追加・シーケンスを追加・ページレイアウトを追加・ビュー定義を追加・帳票を追加・業務フローを追加 (右クリックのメニューは「新規作成」のまま) |
| 画面デザイナの左のタブ | 「項目 (N)」→「**未配置 (N)**」 (部品の「項目」との名前の重なりを避ける。未配置が無いときは「項目」) |
| 新しい処理フローの深さ | 一覧から作ったフローは「ラフ」で始まる (`presetEditLevel`。すでに覚えている深さがあれば、上書きしない)。すでにあるフローは、これまでどおり「実装」 |

## 3. 範囲を絞った点 (理由つき)

- **ID の「仮の ID」を最初から入れておく (#1528 c): していない**。意味のない ID を、利用者が気づかないまま入れると、ファイル名・URL・参照に使われる ID が、あとで困る。「仮の ID を付ける」の案内 (ID 欄の下。画面・処理フロー共通の部品) は、すでにある
- **AI (MCP) で同じ例題を通す評価 (#1528 h): していない** (この環境では、AI の接続が使えなかった)
- 「押せない理由」は、**共通の帯の案内**として出す。個々のボタン (「カラム追加」など) の title は、これまでどおり
