# 操作性 — 仕様書 (改善提案 第 4 弾)

**Status**: 実装済 (2026-10)
**関連**: [list-common.md](list-common.md) / [quick-open.md](quick-open.md) / [screen-layout.md](screen-layout.md) / [grid-keyboard.md](grid-keyboard.md) / [file-backup.md](file-backup.md)

毎日触る人の手間を減らす機能のまとめ。原本 (設計の JSON) の形は変えない。表示の設定・お気に入り・スニペットなど「その人の道具」は、**このブラウザの設定** (localStorage / sessionStorage) に持つ。

## 1. 通知の履歴 (ヘッダーの 🔔)

- `showToast` の通知を、直近 50 件、新しい順に残す。見ていない失敗の数を、🔔 の印に出す
- 失敗の通知には、同じ操作をもう一度できるものだけ「再試行」が付く (通知にも履歴にも出る)。`reportFailure(err, 名前, retry)` / `runReporting(fn, 名前)`。保存の失敗が対象。再試行でまた失敗しても、同じ文言の 5 秒の抑制で通知が消えないよう、再試行の前に抑制を解く
- 実装: `utils/toast.ts` (履歴) / `components/common/NotificationHistory.tsx`

## 2. 表示の設定 (ヘッダーの `Aa`)

| 設定 | 値 | 仕組み |
|---|---|---|
| 文字サイズ | 小 0.9 / 標準 / 大 1.15 / 特大 1.3 | `<html data-font-scale>` → `--hm-font-scale`。CSS の `font-size` は `calc(Npx * var(--hm-font-scale))` で書く (`npm run check` の「文字サイズの検査」が、px の直書きを止める。`node scripts/dev/scale-font-sizes.mjs --write` で直せる)。rem / em は、html の文字サイズ (rem の基準) と親から引き継ぐ |
| 密度 | 標準 / コンパクト | `<html data-density>` → `--hm-row-py` (表の行の縦の余白。一覧・画面項目・分析・工程表・「表で編集」) |
| コントラスト | 標準 / 高 | `<html data-contrast>` → 淡い文字と罫線の色トークンを濃くする |

- 画面デザインの紙面・帳票の見本は、設計対象アプリの見た目なので、文字サイズの設定を受けない (`.sld-paper` / `.rpe-paper-wrap` で倍率を 1 に戻す)。印刷も受けない
- 画面内のインライン style の文字サイズ (`fontSize`) と、React Flow の図の中の一部の文字は、設定の対象外
- 保存先: localStorage `harmony.display`。実装: `theme/displayPrefs.ts` / `components/common/DisplaySettings.tsx`

## 3. お気に入り (ヘッダーの ★、クイックオープンの ★、ダッシュボードのパネル)

- 設計 (画面・画面項目・テーブル・処理フロー・業務フロー・帳票・シーケンス・ビュー・ビュー定義・ページレイアウト・ガジェット) を固定する。タブの「ピン留め」(タブの並びの固定) とは別
- ワークスペースごと、最大 30 件、固定した順。localStorage `harmony-favorites:<wsId>`。削除・改名で見つからなくなったものは「見つかりません」と出す (自動では消さない)
- ガジェットと画面は同じタブ (画面デザイナ) で開くので、どちらの印で固定しても同じものとして扱う

## 4. コマンドパレット

`Ctrl+K` のあと `>`、または `Ctrl+Shift+P`。操作の一覧は `components/quick-open/paletteCommands.ts`。

- いまのタブへの操作: 保存 (未保存のとき) / 元に戻す / やり直す / タブを閉じる / ほかを閉じる / ピン留め / お気に入り。保存・元に戻す・やり直し・閉じるは、各編集画面が持つキー (Ctrl+S / Z / Y / W) をそのまま送る (画面ごとの処理を、パレットは持たない)
- 配色・文字サイズ・密度・コントラスト / 表示の設定・通知の履歴・ショートカット一覧・検索置換・操作ツアー / 並べて表示を閉じる / 最近の履歴・通知の履歴を消す
- 「削除」のように、取り返しのつきにくい操作はパレットに入れない

## 5. 変更履歴・一括変更・別画面へのコピー・スニペット

### 5.1 変更履歴 (編集ヘッダーの 🕘)

`useUndoableState` が積んでいる操作 (50 件) を、時間順に一覧し、行を選ぶと**その操作の後の状態へ一度に**移る (`jumpTo(n)`)。操作の呼び名は、前後の状態の差 (`jsonDiff`) から自動で作る (「カラム › 注文ID › 表示名を変更 (A → B) ほか 2 件」)。操作に名前は付いていない。Ctrl+Z / Ctrl+Y と同じ履歴で、保存済みの内容は変わらない。対象: テーブル・処理フロー・画面デザイナ・規約カタログ (編集ヘッダー)、業務フロー・帳票 (ツールバー)

### 5.2 一括変更 (テーブルのカラム・画面項目)

選んだ行に、型・長さ・NOT NULL などを**予行を見てから**まとめて設定する (`utils/bulkEdit.ts`)。その行に設定できない項目 (型が文字列でない行の最大長など) は、飛ばして理由を見せる。同じ操作でデータ型も変えるなら、新しい型で判定する。確定は編集中の内容への変更で、保存するまで残らず、Ctrl+Z で戻る。

### 5.3 共有のクリップボード

カラム・画面項目・工程は、種類ごとの共有のクリップボード (メモリのみ) で、別のテーブル・画面・処理フローへ貼り付けられる (`useListClipboard` の `share`)。

- 貼るとき、新しい ID を付ける (そのままだと、同じ ID の行が 2 つになる)。物理名・項目 ID が重なれば `_copy` / `Copy` を付ける。別の画面・テーブルからは、重なるとき確認する
- 別のテーブルから貼るとき、貼り先にすでに主キーがあれば、貼るカラムの主キー・自動採番の印は外す
- **別の編集画面から切り取ったものは、元を消せないので、コピーとして貼る**
- 画面項目にも、コピー / 貼り付け (Ctrl+C / V、ボタン) を足した。工程の貼り付けは、別の処理フローの工程の変数・ジャンプ先の参照が、貼り先で合うかを、利用者が確かめる

### 5.4 スニペット

選んだカラム・画面項目・工程を、名前をつけて残し (最大 100 件・1 件 200 要素)、あとで挿入する。このブラウザ (ワークスペースごと) に保存し、JSON の書き出し / 読み込みで人に渡せる。読み込みは、形の違うもの・同じ種類で同じ名前のものを飛ばし、ID は付け直す。

## 6. 設計全体の検索置換 (`Ctrl+Shift+H`)

名前・ラベル・説明・備考などの**文章**から語を探し、見つかった一覧 (置換後の文言つき) から**選んだものだけ**を置換する。仕様の要点:

- 置換する欄: `name / label / description / comment / title / message / note / text / purpose / placeholder / helperText`。ID・参照・物理名・パス・式・SQL・条件式・既定値には触れない (ID の変更は「ID の変更」で、参照も一緒に直す)。`@` で始まる参照つきの文言、識別子だけの `name`、汎用定義の `name` (ファイル名・参照に使う識別子) は対象外
- 対象の設計: 画面・テーブル・処理フロー・業務フロー・帳票・シーケンス・ビュー・ビュー定義・ページレイアウト・汎用定義。画面デザインの旧形式 (`*.design.json`)・旧 `actions/` は対象外
- 予行 (`designReplace.preview`) は何も書かない。適用 (`designReplace.apply`) は、選んだ項目を**再走査**し、予行で見せた文言のままのものだけ置換する (予行のあとに変えられたものは飛ばす)。編集中 (誰かが編集モードで開いている。自分の編集中も) の設計は飛ばす (あとの保存で、置換が巻き戻るため)
- 探す語は文字どおり (正規表現の記号もそのまま)。大文字小文字は、指定したときだけ区別する。置き換える語の `$&` などもそのまま
- 取り消し (`designReplace.undo`): 30 分以内。置換のあとで変えられたファイルは、戻さずに知らせる。書き換える前の内容は、保存前の版 (`.harmony-backups`、[file-backup.md](file-backup.md)) にも残る。複数ファイルの書き換えは、先に復旧用の記録 (`.harmony-journal`) を残す
- AI (MCP) からは使えない (一括の書き換えは、利用者が画面で確かめて行う)

## 7. 表で編集 (テーブルのカラム)

カラムのタブの「表で編集」で、表計算ソフトのようにセルをその場で編集する (`components/table/ColumnGrid.tsx`)。Tab / Enter / ↑↓ は [grid-keyboard.md](grid-keyboard.md) と同じ。文字のセルは、セルを出るときに 1 回だけ反映する。並べ替え・コピー・一括変更・詳細パネルは「一覧で編集」で行う。

## 8. キーボード代替 (ドラッグ操作)

ドラッグ操作のある画面は、マウスなしで同じことをする方法を台帳 (`scripts/verify/drag-alternatives.json`) に書く。新しいドラッグ操作を足したのに台帳に無いと、`npm run check` が止める。

| 操作 | 代替 |
|---|---|
| タブの並べ替え | `Ctrl+Shift+PageUp / PageDown`、タブの右クリック「左へ / 右へ動かす」 |
| 一覧の行の並べ替え | 行を選んで `Alt+↑↓` |
| ダッシュボードのパネル | パネルの見出しで `Alt+矢印` (移動)、`Alt+Shift+矢印` (大きさ)。変更は読み上げの通知 (`role=status`) に出る |
| 画面フロー図・ER 図のノード | ノードを選んで矢印キー (React Flow の標準)。**矢印キーでの移動は、React Flow が `onNodeDragStop` に通知しないので、操作が落ち着いたら (0.4 秒) 位置を保存へ回す** (`useKeyboardNodeMove`) |
| 画面フローの遷移を線で引く | 「遷移を追加」ボタン (遷移元・遷移先を選ぶ) |
| 画面デザイナの部品 | `↑↓` 前後の部品、`←` 親、`→` 最初の子、`Alt+↑↓` 同じ入れ物の中で並べ替え、`Alt+←` 入れ物の外へ、`Alt+→` 直前の入れ物の中へ |

画面デザイナは「部品の入れ子」で、座標を持たないので、整列ガイド・スナップ・ミニマップは対象外 (改善提案の前提が違った)。

## 9. 空の状態・ヘルプ・ツアー

- 空の状態: `components/common/EmptyState.tsx` (何も無い / 検索で 0 件 / 最初の 1 件を作るボタン / 絞り込みの解除)。一覧・タブ・カタログ・拡張の空の表示を統一
- 項目ごとのヘルプ: 入力欄の見出しの「?」(`HelpHint`)。話題は `utils/helpTopics.ts` (短い説明と、くわしい仕様書の場所。仕様書はアプリの外 (リポジトリの docs/) にあるので、場所を示す)
- 操作ツアー: `Ctrl+K → 「>」→「ツアー」`。ダッシュボード・テーブル・画面項目・処理フロー・画面デザイナ。初めて開く画面で、ツアーがあることを一度だけ通知する (勝手には始めない)。手順は `utils/tours.ts`
- 「サンプルを作るウィザード」は未実装 (アプリはサンプルを同梱せず、ワークスペースへ複製する仕組みが無い)

## 10. 並べて表示 (タブの右クリック「右側に並べて表示」)

同じアプリをもう 1 つ iframe (`?pane=1`) で右に開き、別の設計を左のタブと並べる。**右ペインは、別のブラウザのタブと同じ扱い**: 編集のロック・下書きは別々で、一方の保存はもう一方へ通知される (編集していなければ自動で読み直す)。キー操作 (Ctrl+S など) は、フォーカスのある側だけに効く。

- 右ペインの中は、ヘッダー・タブバーを出さず、開いているタブの記録 (localStorage) を読まず・書かない (左のタブを上書きしない)。未保存かどうかと、いま開いている画面のパスを、親へ `postMessage` で知らせる (同じオリジン・形式の検査つき)
- 「左で開く」「入れ替え」「閉じる」。右ペインに未保存があれば、閉じる前に確認する (編集中の内容は下書きに残る)
- 左で、右ペインと同じタブを開いたら、右ペインは閉じる (同じ設計を左右で開かない)
- 状態は、このブラウザのタブの中だけ (sessionStorage `harmony.split:<wsId>`)。右ペインは 1 つ

## 11. エラー画面からの復旧

エラー画面 (タブ / アプリ全体) に、「編集中の内容は下書きに残っている」案内 (このブラウザの下書き・サーバの編集セッション) と、「再試行で続きから編集できる」ことを出す。「状況をまとめてコピー」(JSON) には、エラーのログの履歴・ブラウザに残っている下書きの一覧 (中身は含めない)・**サーバのログの末尾 100 行** (`diagnostics.serverLogTail`。書くときにキー・トークンをマスク済み) を含める。

## 12. 画面構造の監査 (スクリーンリーダー向け)

- 全体の構造: ページ全体は `<main id="app-main">` 1 つ、上部は banner (ヘッダー)、タブバーは `<nav aria-label="開いているタブ">`。エディタの題 (`EditorHeader` の title) は `role="heading" aria-level=1`、各ペインの題は h2、それより下は h3 以降 (段を飛ばさない)。通知は `role="status"` の読み上げ領域 (`ToastHost`)
- 検査: `frontend/e2e/a11y-structure.spec.ts` (@smoke) が、主要 23 画面で、main が 1 つ・banner・navigation・見出し (段の飛びなし)・読み上げ領域・名前の無い dialog・alt の無い画像・aria-hidden の中のフォーカス可能な要素を確かめる。操作部品の名前は `a11y-names.spec.ts`
- **実際のスクリーンリーダー (NVDA・VoiceOver) での確認は含まれない** (機械で確かめられる構造だけ)

## 13. 狭い画面 (タブレット幅)

`npm run ui:narrow` (`scripts/dev/narrow-audit.mjs`) が、全主要画面を 1024px / 768px (指定可) で開き、ページ全体の横はみ出し・スクロールできない入れ物の外へ出た要素・ヘッダーの操作が画面の外へ出るものを検出する。エディタのヘッダーは、1100px 以下で折り返す (`editorHeader.css`)。スマートフォン幅 (640 / 420px) は、ダッシュボード・テーブル一覧で確認した。
