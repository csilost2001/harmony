# 0002 SQL は工程に直接書く

**状況**: SQL を、MyBatis のように別のファイルで管理し、処理フローから呼ぶ形にすべきか。

**決めたこと**: 現状のまま、`dbAccess` 工程に SQL を直接書く。

**理由**: 処理の流れと SQL を一緒に読めること (設計書・「流れ」・レビュー)。結果の形 (1 件か一覧か) の推定、変数の流れ、SQL のカラムと型の確認が、工程の中で完結する。別管理にすると、呼び出し側から結果の形が読めなくなる。

**選ばなかった案**: SQL を別の定義にして参照する (重複の排除はできるが、読む手間が増える)。代わりに、**重複は検出する** — 設計の分析に SQL の一覧 (CSV) と同じ SQL の重複の検出を足した ([design-analysis.md](../spec/design-analysis.md))。

**結果**: 結果が 1 件か一覧かのヒントは、規則がないので断定せず「1 件を返す設計なら直さないで」と出す。
