# 0008 kind で 1 組の tool、まとめての編集はファイルだけ

**状況**: シーケンス・ビュー・ビュー定義・汎用定義 (17 種) を AI が扱えなかった。種類ごとに list / get / save / delete を作ると 70 個近く増える。工程を複数直すときは 1 つずつ呼ぶしかなく、途中で止まると中途半端になる。

**決めたこと**: (1) 4 種の設計は `kind` で選ぶ 1 組の tool (`list_designs` `get_design` `save_design` `delete_design`)。既存の画面・テーブル・処理フローなどの tool は変えない。(2) `edit_steps` は工程の編集を**全部成功するか何も保存しない**形でまとめて適用し、既定は予行。対象は**保存済みのファイルだけ** (画面で開いている処理フローは断る)。

**理由**: tool の説明は毎回文脈に載る。画面で開いている内容 (未保存かもしれない) に一括で適用すると、人の編集を壊し得る。

**選ばなかった案**: 種類ごとの tool / 画面の内容へも一括で適用 / 各 `save_*` に `dryRun` を付ける (tool ごとの差が大きい。代わりに `validate_design` と予行)。

**結果**: [mcp-design-access.md](../spec/mcp-design-access.md)。画面で開いているかの確認は、最後に接続した 1 つのブラウザだけが対象 (限界として明記)。
