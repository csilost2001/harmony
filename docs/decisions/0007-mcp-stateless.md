# 0007 MCP は stateless。通知は押し出さない

**状況**: 画面で人が設計を直したとき、AI へ通知する (リソースの購読) 案があった。冪等キー・進捗通知も同じ理由で検討した。

**決めたこと**: MCP の接続は HTTP の要求ごとにサーバを作り直す方式のまま (複数の AI が同時に接続しても、互いの状態に干渉しない)。サーバから AI へ押し出す通知・冪等キーの記憶・進捗通知は実装しない。

**理由**: 押し出す通知と記憶は、接続をまたいで状態を持つ必要がある。いまの方式の利点 (干渉しない・再起動に強い) を捨てるほどの要望がない。

**代わりに**: `designer__get_changes_since` で、必要なときに聞く。`save_*` `update_*` `delete_*` は元から冪等で、`add_*` の再送は一覧で確かめられる (注釈の `idempotentHint` で区別)。

**結果**: [mcp-design-access.md](../spec/mcp-design-access.md)。stateful にする要望が出たら、新しい記録で置き換える。
