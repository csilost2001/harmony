# Harmony 再設計計画 (2026-10)

改善提案書 (HMY-PROP-001、Opus 5.5 作成、2026-10-08) に対する設計者判断と、それに基づく実施計画。

## 設計者判断 (2026-10-08 確定)

| 論点 | 判断 |
|---|---|
| 画面エディタを 1 方式に絞るか | **絞る**。CSS framework の違いはプレビューの描画テーマで吸収し、原本 (JSON) に描画方式を持たせない |
| 画面スキーマに「部品の木」を加えるか | **加える** (#511 schema governance の設計者承認済)。既存項目を壊さない追加として導入する |
| AI 運用ルールの削減 | **賛成**。機械的に実現できる処理・繰り返す処理は可能な限りスクリプト化する |
| Excel 出力 | **当面非サポート**。HTML 出力 (設計書ビュー) を優先。Excel 出力は将来追加。顧客別 Excel フォーマットの取込 (AI 解析 → JSON 化) は将来検討 |
| 将来要望 | プログラム生成機能の後に、Playwright テストコード生成機能 |

進め方: 段階的に自律実施し、区切りごとに作業ブランチへローカルコミット。成果は HTML 報告書で設計者が確認する。現行要件にこだわらず改善が妥当な箇所は改善してよい。

## 段階

| 段階 | 内容 | 完了条件 |
|---|---|---|
| 0 立て直し | テーマ統一 / 編集開始 UI 整理 / プレースホルダ判別性 / 不正 ID 自動登録の抑止 / AI 運用ルールの整理とスクリプト化 | 全画面が同じ見た目・作法で動く |
| 1 モデル層 + 業務部品 | 参照グラフ・導出 (shared) / 画面スキーマに部品の木 / 業務部品デザイナ / 既存画面の移行 | retail 全画面が新形式で編集できる |
| 2 処理フロー二面ビュー | 自動配置フロー図 + 処理記述表 | 注文確定を図で読み解ける |
| 3 設計書ビューと導出 | 紙面表示 / CRUD 図 / 影響範囲 / HTML 出力 | 設計書を HTML でレビューに出せる |
| 4 設計書種の拡充 | 業務フロー / 帳票 / 権限 / バッチ一覧 / テスト観点 | 要件〜詳細設計を Harmony で完結 |
