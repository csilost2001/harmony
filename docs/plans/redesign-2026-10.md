## 設計者判断 (2026-10-08 確定)

| 論点 | 判断 |
|---|---|
| 画面エディタを 1 方式に絞るか | **絞る**。CSS framework の違いはプレビューの描画テーマで吸収し、原本 (JSON) に描画方式を持たせない |
| 画面スキーマに「部品の木」を加えるか | **加える** (#511 schema governance の設計者承認済)。既存項目を壊さない追加として導入する |

| Excel 出力 | **当面非サポート**。HTML 出力 (設計書ビュー) を優先。Excel 出力は将来追加。顧客別 Excel フォーマットの取込 (AI 解析 → JSON 化) は将来検討 |
| 将来要望 | プログラム生成機能の後に、Playwright テストコード生成機能 |

進め方: 段階的に自律実施し、区切りごとに作業ブランチへローカルコミット。成果は HTML 報告書で設計者が確認する。現行要件にこだわらず改善が妥当な箇所は改善してよい。

### 設計者判断 (2026-10-08 追加)

報告書 (HMY-REPORT-001) の判断事項 4 点について、設計者から「すべて了解。作業ブランチでの開発なので理想どおりに進めてよい」との回答。方針は次のとおり。

- 旧エディタ (GrapesJS / Puck) は削除する。ただし**先に「プロジェクト独自部品」を業務部品デザイナ上で WYSIWYG に作れるようにする** (JSON の手書きは現実的でないため)。削除はその後
- 独自部品 = 部品の木の断片に名前と「差し込み口 (パラメータ)」を付けて登録したもの。使う側は参照ノードで置く。デザイナで部品を組み、範囲選択 →「部品として登録」→ 差し込み口を指定、の操作で作る
- 独自部品の定義と参照ノードは screen スキーマとは別の追加になる。設計者の包括的な了承 (上記) を受けて作業ブランチ上で進めるが、スキーマ追加の内容は仕様書 (`docs/spec/`) に先に書き、報告書で確認を取る
- 段階 4 (権限 → 業務フロー → 帳票) も同様に進める。push は設計者の指示で実施済み (origin/feat/harmony-redesign)。以降も変更の前に push する。PR は別途指示があるまで作らない

### 旧エディタ廃止 (2026-10-08 実施)

設計者判断 (独自部品デザイナを先に用意してから削除) に従い、同日に実施した。

- 削除: frontend のエディタ本体・パネル・ストア・外部 React 部品の読込基盤、MCP ツール 15 本 (`designer__get_html` 等)、backend の handler / ストレージ、
  依存パッケージ (grapesjs / @grapesjs/react / @measured/puck / @monaco-editor/react / tailwindcss / autoprefixer、計 90 パッケージ)、旧エディタ専用の単体テスト約 600 件と E2E 13 spec
- 代替: 画面デザイン = 業務部品デザイナ、カスタムブロック / Puck 登録部品 = プロジェクト独自部品、AI の編集 = `designer__get/set_screen_layout` と独自部品のツール、
  ページレイアウトの合成プレビュー = 画面レイアウトの読み取り専用描画
- 未移行の画面: 開始画面から「旧デザイン (HTML) の自動変換」。Puck の画面は自動変換できないため空の画面から作り直す (旧データのファイルは削除しない)
- 外部 React コードで動く部品は WYSIWYG では作れないため対象外 (設計書では名前・差し込み口・見た目の仕様だけを定義し、実装はコード生成で扱う)

### 残課題 (設計者判断が必要)

- 段階 4 の各設計書はスキーマ追加 (設計者承認) が前提
- uuid を持たない設計ファイルは初回読込時に backend が uuid を書き足す (明示保存モデルの例外)。サンプルは全件 uuid 付きのため現状は発生しない

### 残課題 (実装の続き・設計者判断は不要)

- 編集セッションのリソース種別 `screen` (旧デザイン本体) / `page-layout-design` / `puck-data` は、旧データ・履歴のために種別だけ残してある (書き込み分岐は無し)。種別の整理は編集セッション基盤の改修を伴うため別途
- サンプル (`examples/`) に旧エディタ時代のデザインファイル (`*.design.json`) と画面の `design` 参照が残っている (自動変換のテスト入力にも使っている)。サンプルから外す場合は、変換の E2E を別の入力に差し替える
- 画面項目 ID の改名 (`designer__rename_screen_item`) は、未移行の画面の旧デザイン HTML も書き換える処理を残している
- 独自部品の差し込み値のうち遷移先の画面 ID は、画面 ID の改名で自動更新しない (検証で警告)
- `docs/html` (仕様書 HTML) は `npm run docs:build` で再生成する必要がある
